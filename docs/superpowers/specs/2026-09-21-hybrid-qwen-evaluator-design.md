# Qwen 混合评估器优化设计

## 1. 目标

在保留现有离线 Mock Judge 可复现性的同时，增加稳健的 Qwen 语义评估层，解决当前 Qwen 单个非关键字段为空时导致整批任务失败的问题，并让用户可在项目根目录安全地配置 `.env`。

本次优化不以“把 64.49 分调高”为目标。64.49 是被测自动回复的离线质量分，评估器质量将通过人工参考排序相关、问题标签匹配率、Mock/Qwen 分歧和人工抽检评估。

## 2. 已确认的根因

`qwen-plus` 已成功返回 JSON，但其 `improvement` 为空字符串。当前提示词的示例明确写了 `"improvement": ""`，而本地解析器要求该字段必须非空，导致提示词与解析契约相互矛盾。

`qwen-3.7` 和 `qwen-3.8` 的 404 属于模型 ID 配置错误，不是评分代码故障。默认仍使用已成功进入推理的 `qwen-plus`，用户可根据自己账号和地域的实际权限替换为官方模型 ID。

## 3. 运行模式

CLI 保留并新增三种明确模式：

- `--judge mock`：完全离线，用于回归检查和无密钥环境。
- `--judge qwen`：仅使用 Qwen，用于观察单模型评分。
- `--judge hybrid`：推荐模式，对每条 case 同时运行 Mock Judge 和 Qwen Judge，再由本地确定性融合器生成最终结果。

Mock 结果不会被 Qwen 输出覆盖，Qwen 结果也不会被隐藏。报告将保留三组分数，便于审计。

## 4. 融合规则

每项指标按以下公式融合：

```text
hybrid_metric = round(qwen_metric * 0.70 + mock_metric * 0.30, 2)
```

选择 70/30 的原因：Qwen 更适合判断隐含意图、服务闭环和情绪适配；Mock 提供稳定的无证据声明、自助转移和已知高风险信号。该权重是可解释初始值，不声称已经统计最优。

其他融合规则：

- `risk_tags` 取 Mock 与 Qwen 的去重并集。
- 任一 Judge 返回 `critical_fail=true`，最终即为 `critical_fail=true`，综合分上限仍为 59。
- 每项融合评语同时保留 Qwen 和 Mock 的理由，不生成新的不可追溯文本。
- 改进建议优先使用 Qwen 非空建议；如果为空，使用 Mock 的确定性建议。
- 评估元数据记录 Qwen 模型、提示词版本、Mock 版本和融合版本。

## 5. Qwen 结构化输出与重试

### 5.1 契约修正

- 提示词中的 `reason`、`evidence` 和 `improvement` 示例改为真实非空文本。
- 提示词明确说明每项 `reason` 和最终 `improvement` 不得为空。
- 分数、指标名、布尔字段和严重风险理由仍使用严格本地校验。

### 5.2 可恢复与不可恢复错误

可恢复错误最多重试一次：

- 返回内容不是 JSON。
- JSON 缺少字段、字段类型不对或分数越界。
- `reason` 或 `evidence` 不满足契约。

重试请求会附加简短的本地校验错误，要求模型只重新返回合法 JSON，不包含原始 API Key 或完整底层异常。

不重试错误：

- 401/403：密钥或权限错误。
- 404：端点或模型 ID 不存在。
- 其他明确配置错误。

429 和 5xx 最多重试一次；不在代码中进行长时间阻塞等待。

### 5.3 非关键字段降级

`improvement` 是辅助性文本，不影响五项分数和安全判断。如果唯一错误是 Qwen 返回空 `improvement`，不额外消耗 API 重试，而是使用本地确定性建议：

- Qwen-only 模式：根据最低分指标选取固定改进模板。
- Hybrid 模式：使用 Mock Judge 的改进建议。

报告元数据记录 `local_improvement_fallback=true`，避免用户误以为该建议由 Qwen 原始输出。

## 6. `.env` 配置

新增标准库实现的简单 `.env` 加载器，不引入 `python-dotenv` 依赖。

优先级：

1. 当前 shell 已存在的环境变量。
2. `--env-file` 显式指定的文件。
3. 项目当前目录的 `.env`。
4. 代码默认值。

已存在的 shell 变量不会被 `.env` 覆盖。加载器只读取 `QWEN_API_KEY`、`QWEN_BASE_URL` 和 `QWEN_MODEL`，支持简单的 `KEY=value` 和单/双引号，不执行 shell 命令、变量展开或代码。

`.env` 继续由 `.gitignore` 忽略，`.env.example` 只包含空密钥和安全示例。程序不打印、不写入报告、不将密钥放入异常信息。

## 7. 错误消息

- 404 将提示检查 `QWEN_MODEL`、`QWEN_BASE_URL` 与账号地域，并显示当前模型名，但不显示密钥。
- 401/403 将提示重新生成密钥并检查模型权限。
- 格式重试仍失败时，错误包含 case ID、尝试次数和最终本地校验错误。
- CLI 明确打印本次使用的 Judge 模式和 Qwen 模型，不让用户把 Mock 结果当成 Qwen 结果。

## 8. 报告变更

Hybrid 报告每条 case 增加：

- `mock_metrics`
- `qwen_metrics`
- `metrics`（最终融合值）
- `judge_disagreement`（五项指标绝对差及最大差值）
- `local_improvement_fallback`
- Qwen 实际请求次数

整体报告增加：

- Mock、Qwen、Hybrid 三组指标均值。
- 分歧最大的 3 条 case，便于人工复核。
- 格式重试次数和本地建议降级次数。
- 人工参考分别对 Mock、Qwen 和 Hybrid 计算验证指标。

人工参考仍不会发送给 Qwen，也不参与融合分数计算。

## 9. 测试

按 TDD 增加：

- `.env` 读取、引号、白名单、shell 变量优先级和不执行输入测试。
- Qwen 空 `improvement` 的本地降级测试。
- 非 JSON、缺失字段和越界分数的一次重试测试。
- 401/403/404 不重试和脱敏错误测试。
- 429/5xx 最多一次重试测试。
- 70/30 分数融合、风险标签并集和 `critical_fail` 传播测试。
- Hybrid CLI 端到端测试，网络层使用本地替身，不消耗真实额度。
- 报告中三组分数、分歧排序和调用次数的一致性测试。
- 新增密钥泄漏扫描和 Git 忽略检查。

真实 Qwen 运行由用户使用新生成的密钥在本地执行。实现和 CI 验证不使用用户密钥。

## 10. 成本与验收

- Hybrid 对 20 条数据通常产生 20 次 Qwen 请求。
- 每条只在可恢复错误时最多重试一次，极端上限为 40 次。
- Qwen 返回空 `improvement` 不重试，因此用户已遇到的错误不会额外消耗请求。
- Mock 模式原有命令和报告保持兼容。
- 完整测试通过，且不进行真实 API 请求。
- README 给出 `.env` 和 shell 两种配置方式，并明确推荐 `qwen-plus`。
- 报告可区分 Mock、Qwen 和 Hybrid 分数，不会把三者混为一个不可解释的数字。
